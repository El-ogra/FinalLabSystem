# LIS PDF Reference Extractor — FinalLabSystem

> **هدف المهارة الوحيد:** تحويل PDF مرجعي لنظام إدارة معامل (Real Lab System / LIS) إلى **وثيقة متطلبات قابلة للتنفيذ** ومُنظّمة بحيث يستطيع المطوّر غير البرمجي مراجعتها قبل أن يبدأ الوكيل بأي تنفيذ.

---

## متى تستدعى هذه المهارة

| الموقف | الوكيل يستدعي المهارة؟ |
|--------|------------------------|
| أرسل المستخدم ملف PDF وقال: «حلله» / «استخرج متطلبات» | ✅ نعم |
| أرسل المستخدم ملف PDF وقال: «قارنه بمشروعنا» | ✅ نعم |
| أرسل المستخدم ملف PDF وقال: «هذا نظام مشابه لما أريده» | ✅ نعم |
| أرسل المستخدم ملف PDF وقال: «اقرأ هذا العقد» | ❌ استخدم `pdf` أو `pdf-official` |
| أرسل المستخدم ملف PDF لتقرير مريض | ❌ لا علاقة |

**شرط أساسي:** الملف PDF **لنظام LIS** (وليس تقريرًا فرديًا). إذا لم يكن كذلك، اسأل المستخدم قبل المتابعة.

## المسار الكامل للمهارة — 7 مراحل

### المرحلة 1 — استكشاف أولي (5 دقائق)

**قبل لمس الملف:**
1. اقرأ `FinalLabSystem/Docs/FinalLab_Modules_Documentation.md` لفهم ما هو موجود فعلاً.
2. افحص `FinalLabSystem/Models/` لاكتشاف الكيانات الموجودة (`Patient`, `Visit`, `TestResult`, ...).
3. افحص `FinalLabSystem/Services/Interfaces/` لاكتشاف الخدمات الموجودة.
4. لاحظ آخر migration في `FinalLabSystem/Migrations/`.

**الناتج:** قائمة مختصرة «ما هو موجود في FinalLabSystem» (سطرين لكل موديول).

### المرحلة 2 — استخراج نص PDF (10-30 دقيقة حسب حجم الملف)

**الأدوات المعتمدة بالترتيب:**

```python
# الخطوة 1: تحويل PDF إلى Markdown مع الحفاظ على الجداول
# استخدم pdfplumber للجداول، و pypdf للنص العادي

import pdfplumber
from pathlib import Path

def extract_pdf(pdf_path: str, output_md: str):
    """يستخرج كل صفحات PDF إلى Markdown مع جداول."""
    with pdfplumber.open(pdf_path) as pdf:
        md_lines = [f"# {Path(pdf_path).stem}\n"]
        for i, page in enumerate(pdf.pages, 1):
            md_lines.append(f"\n## صفحة {i}\n")
            text = page.extract_text() or ""
            md_lines.append(text)
            for table in page.extract_tables():
                md_lines.append("\n### جدول\n")
                if table:
                    header = table[0]
                    md_lines.append("| " + " | ".join(str(c) for c in header) + " |")
                    md_lines.append("| " + " | ".join("---" for _ in header) + " |")
                    for row in table[1:]:
                        md_lines.append("| " + " | ".join(str(c) for c in row) + " |")
    Path(output_md).write_text("\n".join(md_lines), encoding="utf-8")
```

**قواعد الاستخراج:**

1. **نص OCR:** إذا كان الـ PDF عبارة عن صور (scan)، نفّذ OCR أولاً عبر `pytesseract` على صور `pdf2image` قبل أي شيء آخر.
2. **حجم الصفحات:** إذا كان الـ PDF أطول من 100 صفحة، اقترح تقسيمه إلى أجزاء قبل المتابعة.
3. **اللغة:** إذا كان المستند PDF مكتوبًا بلغة غير العربية والإنجليزية، اسأل المستخدم عن ترجمته أو تجاهل.
4. **احفظ الناتج:** `Docs/PRDs/<ModuleName>/_extracted/<OriginalName>.md` (لا تعرضه على المستخدم، استخدمه أنت فقط).

### المرحلة 4 — تحليل الفجوات (30 دقيقة)

**المخرج:** `02-Gap-Analysis.md`.

**لكل عنصر في الفهرس** (شاشة/وظيفة/تقرير/قاعدة)، صنّفه في إحدى 5 فئات:

| الفئة | الرمز | المعنى |
|-------|-------|--------|
| **موجود بالكامل** | ✅ | الميزة موجودة في FinalLabSystem وتعمل كما في المرجع |
| **موجود جزئيًا** | 🟡 | بعض الأجزاء موجودة، تحتاج تحسين أو إضافة |
| **غير موجود** | ❌ | الميزة غير موجودة وتحتاج إنشاء من الصفر |
| **غير قابل للتطبيق** | ⛔ | الميزة تتطلب تغييرًا معماريًا كبيرًا (مثلاً: سيرفر سحابي) |
| **بحاجة لقرار** | ❓ | غامض — يجب سؤال المطوّر |

**القالب:**

```markdown
# تحليل الفجوات — <اسم النظام المرجعي> vs FinalLabSystem

> تاريخ التحليل: <YYYY-MM-DD>
> المصدر: `01-Reference-Screens-Index.md`
> الفرع الحالي: `before-prd` — آخر migration: <اسم>

## 1. ملخص تنفيذي

| الفئة | العدد | النسبة |
|-------|-------|--------|
| ✅ موجود بالكامل | 12 | 35% |
| 🟡 موجود جزئيًا | 8 | 24% |
| ❌ غير موجود | 11 | 32% |
| ⛔ غير قابل للتطبيق | 2 | 6% |
| ❓ بحاجة لقرار | 1 | 3% |

## 2. تفاصيل الفجوات حسب الفئة

### 2.1 ❌ غير موجود — يحتاج إنشاء

| الميزة | المرجع (صفحة) | FinalLabSystem الحالي | الجهد التقديري |
|--------|---------------|------------------------|----------------|
| تنبيهات SMS للنتائج الجاهزة | 23 | لا يوجد | كبير |
| ... | ... | ... | ... |

### 2.2 🟡 موجود جزئيًا — يحتاج تحسين

| الميزة | الموجود حاليًا | المطلوب حسب المرجع | الجهد التقديري |
|--------|----------------|---------------------|----------------|
| طباعة ملصقات | ZXing.Net + FlowDocument | يدعم أحجام متعددة | متوسط |
| ... | ... | ... | ... |

### 2.3 ❓ بحاجة لقرار

- **سؤال:** هل نريد تطبيق SMS فعلًا أم نكتفي بالإشعار داخل البرنامج؟
  - الخيار A: SMS عبر Twilio → تكلفة شهرية + اعتماد على طرف خارجي
  - الخيار B: إشعار داخلي فقط → بدون تكلفة لكن أقل فائدة
  - **توصية الوكيل:** الخيار B في المرحلة الأولى، SMS كتحسين لاحق

## 3. أولويات مقترحة

1. **أولوية قصوى:** الشاشات المكسورة / الحقول المطلوبة قانونيًا (موجودة في المرجع ومنعدمة عندنا)
2. **أولوية عالية:** التقارير التي يطلبها العميل بشكل متكرر
3. **أولوية متوسطة:** تحسينات UX / Workflows
4. **أولوية منخفضة:** ميزات اختيارية
```

## قواعد ذهبية

1. **لا تخترع متطلبات.** كل بند في الوثائق يجب أن يكون مرجعًا لصفحة في PDF أو ملف في الكود.
2. **اللغة العربية.** اكتب الوثائق النهائية بالعربية. أسماء الكيانات والخدمات بالإنجليزية.
3. **الأرقام في كل مكان.** عدد الصفحات، عدد الاختبارات، عدد الشرائح، الجهد التقديري.
4. **لا تتجاوز 8 شرائح في خطة عمل واحدة.** لو زاد، قسّمها إلى مراحل (Phase A، Phase B).
5. **اعرض على المطوّر قبل التنفيذ.** لا تتخطى المرحلة 6 أبدًا.

## 🔗 الربط مع المهارات الأخرى — الترتيب المعتمد للمهام

هذه المهارة **الخطوة الأولى** في سلسلة تحليل نظام مرجعي، ولا تعمل بمعزل عنها:

```
1) lis-pdf-reference-extractor  ← أنت هنا (تستخدم أولاً)
        │
        ▼   (ينتج: PRD + خارطة الفجوات)
2) lis-work-plan-with-validation-gates
        │
        ▼   (ينتج: Work Plan بشرائح + Validation Gates)
3) implement  (لتنفيذ شريحة تلو شريحة بـ TDD)
        │
        ▼   (ينتج: كود + اختبارات + Handoff بعد كل شريحة)
4) lis-session-handoff  (بعد كل شريحة تنفيذ)
```

### القاعدة الذهبية

- **`lis-pdf-reference-extractor` تُستدعى أولاً** لأنها تنتج الـ PRD ووثيقة الفجوات.
- **بعدها مباشرة، استدعِ `lis-work-plan-with-validation-gates`** لتحويل الفجوات إلى خطة تنفيذ.
- لا تدخل مرحلة `implement` قبل أن يوافق المستخدم على مخرجات هاتين المهارتين.

### تحويل صريح للمهارة التالية

عند نهاية جلسة PDF Extractor، أنهِ ردّك بالجملة التالية حرفياً:

> «انتهيت من مرحلة الاستخراج والمقارنة. لبدء خطة التنفيذ، استدعِ الآن مهارة **`lis-work-plan-with-validation-gates`** مع اسم الموديول المستهدف.»
